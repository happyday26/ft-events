# P0 acceptance criteria (Given / When / Then)

## E1 — Zero-friction start
**Given** a visitor opens Rootline with no account  
**When** the app loads  
**Then** an editable root node (“Central idea”) is on the canvas immediately

## E2 — Keyboard-first editing
**Given** a node is active  
**When** the user presses `Enter` / `Tab` / `F2`  
**Then** a sibling is inserted / a child is inserted / the node enters edit mode  
**And** drag-and-drop reparents nodes (Drag plugin)

## E3 — Progressive disclosure
**Given** the default chrome  
**When** the user looks at the toolbar  
**Then** ≈6 primary controls are visible (Undo, Redo, Child, Layout, Fit, Export) with More for secondary tools

## E4 — Invisible autosave
**Given** the user edits the map  
**When** ~350ms elapses without further edits  
**Then** the document is written to IndexedDB without a save dialog

## E5 — Performance budgets
**Given** CI runs `npm test`  
**When** keystroke-path and 1,000-node suites execute  
**Then** average keystroke work `<50ms` and 1,000-node adapt/migrate `<1s`

## E6 — Paste nested list → subtree
**Given** a nested markdown/plain list is on the clipboard  
**When** the user pastes onto the map  
**Then** a matching hierarchical subtree is created under the target

## E7 — Command-based writes
**Given** any mutation (insert, layout, template, AI replace)  
**When** it is applied  
**Then** it goes through `CommandBus` (aligned with `execCommand`) so sync can replay later
